Модель данных (6 полей, требовалось не менее 5)

DELETE /items/{item_id}  удаление

Валидация и обработка ошибок
----------------------------
- схемы Pydantic v2 с аннотациями типов и ограничениями (ge, le, min_length,
  max_length), примеры значений для Swagger;
- доменные исключения NotFoundError (404), ConflictError (409),
  BusinessRuleError (409) заменяют исключения SQLAlchemy в едином формате
  {"detail": ..., "error_type": ...};
- нарушение уникальности ISBN дополнительно перехватывается обработчиком
  IntegrityError, поэтому конкурентные вставки тоже дают 409, а не 500;
- ограничения на уровне таблицы: total_copies >= 0 и
  0 <= available_copies <= total_copies;
- проверка бизнес-правила: нельзя уменьшить total_copies ниже числа
  выданных экземпляров; нельзя удалить книгу, у которой есть выдачи.

Найденная и исправленная ошибка
-------------------------------
Первая версия поиска использовала ilike() и работала неправильно:
запрос «булгаков» не находил книгу с автором «Булгаков М.А.».
Причина - встроенная функция lower() в SQLite меняет регистр только для
символов ASCII. Проверка на уровне SQL:

    SELECT 'Булгаков' LIKE 'булгаков'   ->  0
    SELECT 'Abc'      LIKE 'abc'         ->  1

Исправление: в app/database.py на соединение SQLite регистрируется функция
lower() на Python, корректно работающая с Unicode. Конструкция ilike()
подхватывает её автоматически, а в PostgreSQL, где lower() уже умеет
работать с Unicode, вмешательство не требуется. После исправления поиск
работает в любом регистре - это видно в пунктах 9 и 10 лога.
