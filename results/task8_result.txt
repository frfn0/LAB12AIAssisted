Задание 8. Поиск уязвимостей в коде: фактический вывод
=====================================================

Дата проверки: 2026-10-07
Проверялось: FastAPI-приложение, запуск и в Docker с PostgreSQL
Тесты безопасности: 42, всего по проекту 185, покрытие app - 96%

Отчёт в формате методички: что сгенерировал ИИ -> в чём проблема -> как исправил
------------------------------------------------------------------------------

1. Ответ 422 от Pydantic со стандартным телом
   Проблема: в каждой ошибке повторяются входные значения (input, ctx).
   Если в запрос попадут пароль или персональные данные, они вернутся
   клиенту и попадут в логи.
   Исправлено: добавлен обработчик RequestValidationError, который
   отправляет только type, loc, msg.

2. Отсутствие обработчика необработанных исключений
   Проблема: FastAPI отдаёт текст исключения. Ошибка вида
   sqlite://user:secret@host/db раскрывает строку подключения, имена
   таблиц и столбцов.
   Исправлено: добавлен обработчик Exception, клиенту уходит
   "Внутренняя ошибка сервера", детали остаются в логе.

3. Отсутствие защитных заголовков
   Проблема: uvicorn их не выставляет. Без X-Content-Type-Options браузер
   может угадать MIME-тип ответа, без X-Frame-Options страницу можно
   встроить в iframe.
   Исправлено: добавлен SecurityHeadersMiddleware, заголовки ставятся и на
   ошибочные ответы.

4. Попытка убрать заголовок Server в middleware - код не работал
   Проблема: response.headers.pop("server", None) выглядел правильно, но
   uvicorn добавляет заголовок Server на уровне транспорта уже после
   возврата ответа. Тест проходил только потому, что TestClient так не
   делает. На живом сервере заголовок оставался.
   Исправлено: мёртвый код удалён, добавлен флаг запуска --no-server-header
   в Dockerfile и в инструкции README. Добавлен тест, который проверяет
   наличие флага в обоих файлах.

5. Масс-присваивание
   Проблема: ItemCreate создавался без extra="forbid", лишние поля молча
   игнорировались. Клиент с опечаткой или с попыткой подменить id
   получал 201 и не узнавал об ошибке.
   Исправлено: в ItemBase добавлен model_config = ConfigDict(extra="forbid"),
   лишние поля дают 422 extra_forbidden.

6. Незащищённые эндпоинты изменения данных
   Проблема: любой, кто знает адрес, мог создавать, изменять и удалять
   книги.
   Исправлено: добавлена проверка заголовка X-API-Key на POST, PUT и
   DELETE. Чтение осталось открытым, иначе каталог фонда было бы не видно.

7. Сравнение ключа через обычный оператор ==
   Проблема: обычное сравнение завершается на первом несовпадении, и по
   времени ответа ключ можно подбирать посимвольно.
   Исправлено: используется secrets.compare_digest, сравнение постоянного
   времени.

8. Поиск через ilike без экранирования спецсимволов
   Проблема: значение параметризуется, поэтому SQL-инъекция не проходит.
   Но спецсимволы % и _ внутри запроса работали как маски: search=%
   возвращал весь каталог вместо поиска по символу процента.
   Исправлено: добавлена функция _escape_like, символ экранирования
   обрабатывается первым, и в запросе передан escape=LIKE_ESCAPE.
