Проблемы исходной версии, зафиксированные до рефакторинга
-------------------------------------------------------
1. Длина функции больше 30 строк: 66 строк в одной функции.
2. Магические числа: 1.50, 30, 1.5, 500, 5, 0.9 без объяснения смысла.
3. Отсутствие обработки ошибок: неизвестная категория читателя даёт
   KeyError, отсутствие поля id даёт KeyError, строка вместо даты даёт
   AttributeError.
4. Неинформативные имена переменных: l, k, d, dd, f, x, i, r.
5. Дублирование кода: фильтрация выдач читателя повторяется дважды,
   вычисление просрочки не вынесено в отдельную функцию.

Объяснение каждого изменения
-----------------------------
1. Одна функция 66 строк заменена на шесть функций с одной
   ответственностью:
   - overdue_days(due_at, reference) - просрочка в днях;
   - loan_overdue_days(loan, today) - просрочка по выдаче с проверкой данных;
   - fine_for_loan(loan, reader, today, rules) - штраф по одной выдаче;
   - returned_on_time_count(reader_id, loans) - счётчик возвратов вовремя;
   - discount_multiplier(reader_id, loans, rules) - коэффициент скидки;
   - summarize_reader_fine(reader, loans, today, rules) - итог с разбором.
   Публичная функция calculate_reader_fine сохранена с той же сигнатурой,
   чтобы её можно было вызывать как раньше.

2. Магические числа вынесены в неизменяемый объект FineRules:
   daily_rate=1.50, grace_days=30, long_overdue_multiplier=1.5,
   max_fine=500, discount_threshold=5, discount_percent=0.9.
   Теперь правила читаются из кода, а не угадываются, и их можно
   переопределить без изменения логики.

3. Добавлены именованные исключения FineCalculationError,
   UnknownCategoryError и проверки обязательных полей. Вместо
   KeyError('vip') приложение сообщает
   "Неизвестная категория читателя: 'vip'".

4. Имена переменных стали описательными: loan, days, amount, on_time,
   вместо l, dd, f, x.

5. Дублирование устранено: фильтрация выдач читателя и подсчёт просрочки
   встречаются по одному разу. Счётчик возвратов вовремя вынесен в
   returned_on_time_count и используется один раз.

6. Добавлен разбор результата: FineSummary содержит список LoanFine с
   просрочкой, суммой и признаком ограничения по каждой выдаче. В исходной
   версии клиент видел только итоговое число.

7. Деньги считаются через Decimal, а не float: суммы не накапливают
   ошибку представления чисел с плавающей точкой.

8. Режим округления сохранён исходный (ROUND_HALF_EVEN). Это важно:
   при переходе на ROUND_HALF_UP сумма 104.625 стала бы 104.63 вместо
   104.62, то есть рефакторинг изменил бы поведение. Режим зафиксирован
   константой MONEY_ROUNDING с пояснением.

Ошибка, найденная при проверке сохранения поведения
--------------------------------------------------
Первая версия рефакторинга дала 20 расхождений из 200 наборов.
Причина: в quantize_money использовался ROUND_HALF_UP, а исходная версия
округляла режимом Decimal по умолчанию, то есть ROUND_HALF_EVEN.
Пример: 104.625 -> 104.62 в исходной версии и 104.63 в новой.
Исправлено сохранением исходного режима с явным пояснением в коде.
