## Задание 8. Поиск уязвимостей в коде

### Промпт

> ищем да
> давай
> рукодствуйся методичкой

Последняя реплика определяет решение по спорному вопросу: оставить ли
заголовок `X-XSS-Protection`. Методичка перечисляет XSS среди искомых
уязвимостей, поэтому принято решение следовать методичке, а не современным
практикам, и оставить классический набор.

### Результат

Код проверен по всем пунктам задания: SQL-инъекции, XSS, незащищённые
эндпоинты, отсутствие валидации входных данных, незакрытые соединения.

Найдено и исправлено 8 проблем:

1. Ответ 422 от Pydantic повторял входные значения (`input`, `ctx`) —
   добавлен сокращённый формат;
2. Непредвиденные исключения отдавались клиенту целиком, включая строку
   подключения — добавлен обезличенный обработчик `Exception`;
3. Отсутствовали защитные заголовки — добавлен `SecurityHeadersMiddleware`;
4. Попытка убрать заголовок `Server` в middleware не работала, потому что
   uvicorn добавляет его после возврата ответа — добавлен флаг запуска
   `--no-server-header`;
5. Масс-присваивание: `ItemCreate` без `extra="forbid"` — добавлено
   `ConfigDict(extra="forbid")`;
6. Эндпоинты изменения данных были открыты — добавлена проверка
   `X-API-Key`;
7. Сравнение ключа через `==` позволяло подбор по времени ответа — заменено
   на `secrets.compare_digest`;
8. Символы `%` и `_` в поиске работали как маски LIKE — добавлено
   экранирование.

Проверено и оказалось в порядке: SQL-инъекции (четыре вектора), XSS,
подстановка `id`, незакрытые соединения, утечка SQL в ответе о конфликте.

### Неудачные попытки и исправления

| Что пошло не так | Почему | Как исправлено |
|------------------|--------|----------------|
| `AttributeError: 'MutableHeaders' object has no attribute 'pop'` | У заголовков Starlette нет метода `pop` | Удаление переписано через `del`, позже код убран совсем вместе с флагом запуска |
| 22 теста упали после подключения middleware | Ошибка выше ломала каждый ответ приложения | Исправлено, 185 тестов снова зелёные |
| Тест «заголовок Server отсутствует» проходил по неверной причине | `TestClient` не добавляет `server: uvicorn`, в отличие от реального uvicorn | Тест переформулирован; добавлена проверка, что флаг `--no-server-header` прописан в Dockerfile и README |
| Экранирование LIKE ломало реальный поиск | Порядок обработки спецсимволов был неверным: сначала `%`, потом `\` — добавленные обратные слэши удваивались | `LIKE_SPECIALS` обрабатывает символ экранирования первым |
